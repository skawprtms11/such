# 이슈등록

> 코드 `assets/js/pages/issues.js` · 라우트 `#/issues` · [공통 규약](common.md) · [CLAUDE.md](../CLAUDE.md)

주문 처리 과정에서 발생한 문제를 게시판 형태로 등록하고 처리 상태를 관리하는 화면.
화주와 물류사 사이의 소통 창구다.

---

## 접근 권한

| 역할 | 조회 범위 | 등록 | 상태 변경 | 다운로드 |
|---|---|:---:|:---:|:---:|
| 관리자 | 전체 | ✅ | ✅ | ✅ |
| 용마담당자 | 전체 | ✅ | ✅ | ✅ |
| 화주관리자 | 전체 | ✅ | ❌ | ✅ |
| 화주영업팀 | **본인 등록건만** | ✅ | ❌ | ✅ |

**등록은 모든 역할이 할 수 있다.** 다른 화면과 달리 `createOrder` 권한을 보지 않는다.
누구나 문제를 제기할 수 있어야 하기 때문이다.

상태 변경(select) 노출 조건:

```js
can(user, 'updateStatus') || can(user, 'manageUsers')
```

→ 실질적으로 **관리자와 용마담당자**만 상태를 바꾼다.
문제를 접수하고 해결하는 주체가 물류사이기 때문이다.

---

## 화면 구성

### 상단 — 요약 (4칸)

전체 이슈 / 접수 / 확인중 / 종결 건수. 조회된 행 기준이다.

### 필터

| 항목 | 기본값 |
|---|---|
| 상태 | 전체 (`접수` `확인중` `종결` 중 선택) |
| 제목 / 주문번호 | 없음 (부분 일치) |

### 표 (웹)

| 컬럼 | 비고 |
|---|---|
| 연번 | 역순 |
| 등록일자 | **날짜+시각** (`YYYY-MM-DD HH:MM`) — 다른 화면은 날짜만 |
| 유형 | 회색 태그 |
| 제목 | 클릭 시 상세 모달 |
| 확인요청일 | |
| 상태 | 색상 배지 |
| 관리 | 상태 변경 select (권한자만) / `-` |

### 모바일 표 (860px 이하) 🔑

앱 화면은 **조회 전용**이라 컬럼 4개만 둔다.

```
연번 · 등록일자(월/일) · 유형 · 제목
```

- **행 어디를 눌러도 상세 팝업이 열린다** (`bindDetail`). 확인요청일·상태·본문은 상세에서 본다
- 등록일자는 `08/31` 형식으로 줄인다 (`monthDay()`)
- **상단의 `다운로드` · `이슈 등록` 버튼은 나오지 않는다** (`drawHeadActions`)
- 필터는 한 행에 `상태`(110px 고정) · `제목/주문번호`(남는 폭) · `조회` 를 넣는다
- 창 크기가 기준점을 넘나들면 상단 버튼과 표를 다시 그린다

## 등록 폼

| 항목 | 필드 | 필수 | 비고 |
|---|---|:---:|---|
| 유형 | `type` | ✅ | `오출고` `재고부족` `작업요청` `기타` |
| 확인요청일 | `due_date` | ✅ | **기본값 내일** |
| 관련 주문번호 | `order_no` | | 선택 입력. 자유 텍스트 |
| 제목 | `title` | ✅ | |
| 내용 | `content` | ✅ | textarea |

유형 목록은 `config.js` 의 `ISSUE_TYPES` 가 유일한 출처다.

등록 시 상태는 항상 `접수` 로 시작한다 (`db.createIssue()` 의 기본값).

⚠️ **`order_no` 는 주문 테이블과 연결되어 있지 않다.** 단순 문자열이다.
오타가 나도 검증하지 않으며, 주문 화면에서 관련 이슈를 역으로 조회할 수 없다.
연결이 필요하면 별도 작업이 필요하다.

## 핵심 로직 — 상태 전이

```
접수 ──▶ 확인중 ──▶ 종결
```

| 상태 | 배지 색 | 의미 |
|---|---|---|
| `접수` | 파랑 | 등록됨. 아직 확인 전 |
| `확인중` | 주황 | 물류사가 확인·처리 중 |
| `종결` | 초록 | 처리 완료 |

**순서가 강제되지 않는다.** select 로 어느 상태로든 바로 바꿀 수 있고,
되돌리는 것도 가능하다. 상태 변경 이력은 남지 않는다
(주문의 `order_history` 같은 장치가 이슈에는 없다).

상태값은 `config.js` 의 `ISSUE_STATUS` 를 쓴다.

### 상세 모달

제목 클릭 시 유형 · 주문번호 · 확인요청일 · 상태 · 등록일시와 본문을 보여준다.
본문은 `white-space: pre-wrap` 으로 줄바꿈을 살린다.

## CSV 다운로드

파일명 `이슈내역_YYYY-MM-DD.csv`

```
등록일자, 유형, 제목, 주문번호, 확인요청일, 상태, 내용
```

표에 없는 **내용 전문**까지 포함한다.

---

## 실시간 갱신

`db.subscribe(reload)` — 5초 폴링.
화주가 이슈를 올리면 용마담당자 화면에 5초 안에 나타난다.

---

## 수정 시 주의

- 유형·상태 목록은 `config.js` 에서만 바꾼다. 화면에 문자열로 쓰지 않는다
- 등록 권한을 좁히지 않는다. 모든 역할이 이슈를 올릴 수 있어야 한다
- 확인요청일 기본값이 **내일**이다. 오늘로 바꾸면 당일 처리 압박이 생긴다
- 이슈에는 이력 기능이 없다. 필요해지면 주문의 `addHistory()` 방식을 참고한다
