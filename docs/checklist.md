# 업무체크리스트

> 코드 `assets/js/pages/checklist.js`(웹) · `assets/js/mobile/screens/checklist.js`(앱)
> 라우트 `#/checklist` · [공통 규약](common.md) · [CLAUDE.md](../CLAUDE.md)

담당자별 **업무 누락을 막고 담당을 분명히 하는** 화면.
업무 구분(입고·출고·반품·기타)별 항목을 트리(마인드맵)로 등록하고, 항목마다
**담당자**와 **주기**(일·주·월·수시)를 지정한다. 담당자는 **날짜별로 본인 항목을 체크**한다.

공지사항이 *전체 대상 안내*, 이슈등록이 *개별 건의 문제 제기*라면,
업무체크리스트는 **반복 업무의 이행 확인**이다.

---

## 접근 권한

| 역할 | 조회 | 오늘 할 일 체크 | 항목 관리(등록·수정·삭제) | 남의 항목 대신 체크 |
|---|:---:|:---:|:---:|:---:|
| 관리자 | ✅ | ✅ | ✅ | ✅ |
| 용마담당자 | ✅ | ✅ | ✅ | ✅ |
| 화주관리자 | ✅ | ✅ | ✅ | ✅ |
| 화주영업팀 | ✅ | 본인 담당만 | ❌ | ❌ |
| 현장작업자 | ✅ | 본인 담당만 | ❌ | ❌ |

- 항목 관리 권한은 `config.js` 의 `PERMISSION` 에 있는 **`manageChecklist`** 다.
  화면은 `can(user, 'manageChecklist')`(웹) 으로만 판정하고 역할명을 직접 비교하지 않는다
- 체크 판정은 **`db.canCheckItem(user, item)` 한 곳**에 있다 — 웹·앱이 같은 함수를 쓴다

```
담당자 본인  또는  담당자 미지정(공통 업무)  또는  manageChecklist 권한자(대신 체크)
```

- 서버 RLS 도 같은 기준이다 (`supabase/schema.sql` 의 `can_manage_checklist()`).
  **화면 제어만 믿지 않는다**

## 화면 구성 (웹) — 탭 2개

### 탭 1 「오늘 할 일」 (기본)

```
[◀ 2026-09-09 ▶ 오늘]   담당자 [나 ▾]        7 / 12 ▓▓▓▓░░   [어제 미체크 3건]
┌ 입고 ─────────────────────────────────────────┐
│ ☑ 입고 준비 > 오전 점검  입고 예정표 확인  일  김현장  09:12 김현장  [메모] │
│ ☐ 검수 결과 WMS 입력                      일  김현장              [메모] │
│ ☐ 입고 불량 보고서                     주(화)  이담당              [메모] │
└───────────────────────────────────────────────┘
┌ 출고 ─┐ … ┌ 반품 ─┐ … ┌ 수시 ─┐
```

| 요소 | 동작 |
|---|---|
| 날짜 이동 | `◀` `▶` 로 하루씩, 날짜칸 직접 선택, `오늘` 버튼 |
| 담당자 필터 | 기본 `나`. **`manageChecklist` 권한자만** `전체`·특정 담당자를 고를 수 있다 |
| 진행 막대 | 그 날짜·필터 기준 `체크수 / 대상수`. 100% 면 초록 |
| `어제 미체크 N건` | 전날 미체크가 있을 때만 나오고, 누르면 **전날로 이동**한다 |
| 체크박스 | 켜면 기록 생성, 끄면 기록 삭제. 체크한 **시각·사람**이 오른쪽에 남는다 |
| 메모 | 체크한 항목에만 남길 수 있다. 메모가 있으면 아이콘이 파랗게 표시된다 |

- 카드는 **업무 구분별**로 나뉘고, 주기가 `수시` 인 항목만 마지막 `수시` 카드에 모인다
  (수시는 날짜 개념이 없어 어느 날짜에나 나온다)
- **말단 항목(leaf)만 체크 대상**이다. 상위 항목은 줄 앞의 회색 경로
  (`입고 준비 > 오전 점검`)로만 보인다
- 체크 권한이 없는 항목은 회색 + 체크박스 비활성 상태로 **조회만** 된다

### 탭 2 「항목 관리」 (`manageChecklist`)

마인드맵을 **세로 트리**로 그린다. 가로 마인드맵은 좁은 화면에서 깨진다.

```
[입고] 출고  반품  기타          ← 업무 구분 (CHECK_CATEGORIES 로 고정, 화면에서 추가 안 함)
▾ 입고 준비                      김현장         [+][↑][↓][✎][🗑]
    ▾ 오전 점검                                 [+][↑][↓][✎][🗑]
        입고 예정표 확인   일     김현장         [+][↑][↓][✎][🗑]
        입고 불량 보고서   주(화) 이담당         [+][↑][↓][✎][🗑]
  입고 검수                                     [+][↑][↓][✎][🗑]
[+ 최상위 항목 추가]
```

- 버튼은 전부 **아이콘**이다 (공지사항의 `iconBtn` 과 같은 형태 · `aria-label` 로 뜻을 알린다)
- `+` 하위 추가 · `↑`/`↓` 형제 사이 순서 이동 · `✎` 수정 · `🗑` 삭제
- 편집은 **인라인 폼**이 그 자리 아래에 열린다 (제목 · 설명 · 주기 · 담당자 · 활성)
- 자식이 있는 노드는 앞의 화살표로 **접기/펼치기** 한다
- 삭제는 **하위 항목까지 함께** 지운다(확인 문구로 개수를 알린다). 체크 기록을 남기려고
  행을 지우지 않고 `deleted_at` 만 찍는다(soft delete)
- 하위 항목의 업무 구분은 **상위를 따른다.** 최상위 항목의 구분을 바꾸면 하위도 함께 옮겨진다
- 부모 노드에도 주기·담당자를 둘 수 있지만 **체크 대상은 leaf 만**이다 (부모는 묶음 제목)

## 화면 구성 (앱)

`#/checklist` — 상단바 메뉴(`APP_MENU`)에 있다. **오늘 할 일만** 있고 항목 관리는 없다.

- 날짜 이동(`◀ 날짜 ▶ 오늘`) · 큰 진행 카운터 · `어제 미체크 N건` 버튼
- 업무 구분별 카드, 줄 전체가 터치 영역(최소 48px)이라 장갑을 낀 채 눌러도 빗나가지 않는다
- 담당자 필터가 없다 — **로그인 사용자 본인 담당 항목만** 본다
- 메모는 체크한 항목의 메모 아이콘을 눌러 시트에서 입력한다

## 데이터 (`db.js`)

주기 판정·권한 판정은 **`db.js` 한 곳**에만 있다. 화면은 결과만 그린다.

| 함수 | 설명 |
|---|---|
| `listChecklistItems(f)` | 항목 목록. `category` `includeInactive` `assignee` 로 거른다 |
| `checklistTree(rows)` | 평평한 목록을 `{item, depth, children}` 트리로 묶는다 (순수 함수) |
| `createChecklistItem(payload, user)` | 등록. 상위를 주면 업무 구분은 상위를 따르고 순서는 맨 뒤 |
| `updateChecklistItem(id, patch, user)` | 수정. 최상위의 구분을 바꾸면 하위도 함께 옮긴다 |
| `moveChecklistItem(id, dir, user)` | 형제 사이 순서 이동 (`'up'` / `'down'`) |
| `deleteChecklistItem(id, user)` | 하위까지 soft delete. 지운 개수를 돌려준다 |
| `dueItems(date, {assignee})` | 🔑 **그 날짜에 해야 할 leaf 항목** + `path` + 그 날짜의 `check` |
| `listChecks(date)` | 그 날짜의 체크 기록 |
| `setCheck(itemId, date, on, memo, user)` | 체크/해제. 이미 있으면 메모만 갱신한다 |
| `checklistSummary(date, {assignee})` | `{total, done, missed, prevDate}` — `missed` 는 **전날** 미체크 수 |
| `canManageChecklist(user)` `canCheckItem(user, item)` | 권한 판정 (웹·앱 공용) |

### 주기 판정 🔑

`dueItems()` 안의 `isDueOn()` 이 유일한 출처다. 화면에서 날짜를 다시 계산하지 않는다.

| 주기 | 저장값 | 나오는 날 |
|---|---|---|
| 일 | `daily` | 매일 |
| 주 | `weekly` + `weekday`(0=일 ~ 6=토) | 지정 요일 |
| 월 | `monthly` + `monthday`(1~31) | 지정 일자. **말일 보정** — `31` 이면 그 달 말일(2월은 28·29일) |
| 수시 | `adhoc` | 날짜와 무관하게 항상 |

- **수시는 `어제 미체크` 집계에서 뺀다.** 날짜 개념이 없어 "밀렸다"고 볼 수 없다
- 비활성(`active = false`) 항목과 삭제된 항목은 오늘 할 일에 나오지 않는다.
  항목 관리 탭은 `includeInactive: true` 로 비활성까지 본다

### 테이블

| 테이블 | 주요 필드 |
|---|---|
| `checklist_items` | `category` `parent_id` `title` `description` `cycle` `weekday` `monthday` `assignee_id` `assignee_name` `sort_order` `active` `deleted_at` |
| `checklist_checks` | `item_id` `check_date` `memo` `checked_by` `checked_by_name` `checked_at` · **`unique(item_id, check_date)`** |

- 체크는 **항목·날짜당 1건**이다. 두 사람이 같이 눌러도 한 건만 남는다
- 두 테이블 모두 Realtime 에 올라가 있어 다른 사람의 체크가 즉시 반영된다

## 상수 (`config.js`)

| 상수 | 값 |
|---|---|
| `CHECK_CATEGORIES` | `['입고', '출고', '반품', '기타']` — 화면에서 추가하지 않는다 |
| `CHECK_CYCLE` | `daily` `weekly` `monthly` `adhoc` (저장값) |
| `CHECK_CYCLES` | 표시 문구 `일` `주` `월` `수시` |
| `WEEKDAYS` | `['일','월','화','수','목','금','토']` — 배열 순서가 `Date.getDay()` 와 같다 |
| `cycleLabel(item)` | `주(화)` `월(25일)` 처럼 한 줄로 만든다 (웹·앱 공용) |

## 알려진 제약

- **업무 구분은 상수 고정이다.** 구분을 늘리려면 `CHECK_CATEGORIES` 를 고쳐야 한다
  (탭이 늘면 좁은 화면이 깨지므로 화면에서 추가하지 않기로 했다)
- **미체크 알림은 화면 안의 배지뿐이다.** 푸시·메일 알림은 서버가 필요해 넣지 않았다
- **주기가 겹치는 항목을 한 줄로 합치지 않는다.** 같은 일을 매일·매주 두 번 넣으면
  두 줄로 나온다 (등록할 때 정리한다)
